## 2. 설치 스크립트의 함정 — 반드시 알고 있어라

`B_2_서버설치_D드라이브.ps1` 에는 **실제로 겪은 버그**가 있다. 압축본에 그대로 넣어뒀지만, 동작을 알고 있어야 한다.

**증상:** 스크립트가 `[4] 기존 mediamtx.yml 백업 후 유지` 라고 **초록색으로** 출력하고 넘어간다. 성공처럼 보이지만 실패다.

**원인:** `[1]` 단계에서 MediaMTX 배포 zip을 `Expand-Archive` 하면 그 안에 **기본 `mediamtx.yml` 이 같이 들어 있다.** 그래서 `[4]` 의 `Test-Path` 가 항상 참이 되고, 스크립트가 만들려던 설정(93~128행의 pathDefaults, `api: yes`, D드라이브 recordPath)은 **한 번도 기록되지 않는다.**

**결과:** 서버는 켜지지만 기본 설정으로 돌아간다 — 카메라 0대, 녹화 경로가 `./recordings`(C드라이브), `recordDeleteAfter: 1d`, `api: false`. C드라이브는 여유가 30GB뿐이라 금방 찬다.

**해결:** `mediamtx_B창고_완성본.yml` 의 내용으로 `C:\cctv\mediamtx\mediamtx.yml` 을 **통째로 교체**한다. (이미 적용해 뒀다.)

### 🚨 그래서 절대 하지 말 것

**`B_2_서버설치_D드라이브.ps1` 을 다시 실행하지 마라.**
다시 실행하면 zip을 다시 풀면서 **현재 잘 돌아가는 설정을 기본값으로 덮어쓴다.** 카메라 7대가 전부 사라지고 녹화가 멈추는데, 화면에는 초록색 "설치 완료"가 떠서 알아채기 어렵다.

부득이 다시 돌려야 하면 **먼저 `mediamtx.yml` 을 백업**하고, 실행 후 **반드시 복원**해라.

## 3. 설정 파일에 대해 알아야 할 것

`mediamtx_B창고_완성본.yml` 은 **완전한 단독 설정 파일**이다. MediaMTX는 설정 파일을 **하나만** 읽고 `include` 기능이 없다. 따라서:

- **일부만 잘라 붙이지 마라.** `paths:` 부분만 기존 파일에 덧붙이면 키가 중복되어 서버가 아예 시작되지 않는다.
- 항상 **파일 전체를 교체**하는 방식으로 다뤄라.

### 검증 완료 사항 (v1.19.3 소스코드 대조)

- `yes`/`no` 는 정상 동작한다 (`convertLegacyBools` 전처리가 있음). `true`/`false` 로 바꿀 필요 없다.
- `*AllowOrigin` (단수) 은 **deprecated**. 반드시 복수형 리스트 `*AllowOrigins: ['*']` 를 써라. 이미 반영돼 있다.
- `recordPath` 는 `playback: yes` 일 때 **`%f` 가 필수**다. 빼면 서버가 시작을 거부한다.
- 알 수 없는 키가 하나라도 있으면 **기동 실패**한다. 임의로 키를 추가하지 마라.
- 파일 저장 인코딩은 **UTF-8 (BOM 없음)**. BOM이 붙으면 파싱 에러로 서버가 안 뜬다.
  - PowerShell에서 안전하게 쓰는 법:
    `[System.IO.File]::WriteAllText($path, $yml, (New-Object System.Text.UTF8Encoding $false))`

웹 콘솔은 **A창고 PC가 호스팅**한다. B는 콘솔을 만들지 않는다.

### 4-2. 외장하드 전환 (대표가 주문함, 미도착)

도착하면 다음을 해야 한다. **대표가 요청하기 전에 먼저 건드리지 마라.**

1. 외장하드 드라이브 문자 확인 (예: `E:`)
2. `mediamtx.yml` 에서 두 곳 수정
   - `logFile: E:/cctv/mediamtx.log`
   - `recordPath: E:/cctv/recordings/%path/%Y-%m-%d_%H-%M-%S-%f`
3. 대표가 **40일 보관**을 원한다 → `recordDeleteAfter: 720h` 를 **`960h`** 로 변경
4. `C:\cctv\diskguard.ps1` 의 감시 대상 경로와 드라이브 문자도 함께 수정 (지금은 D 고정)
5. 폴더를 미리 만들어라 — `logFile` 의 상위 폴더가 없으면 **MediaMTX가 기동에 실패한다** (`O_CREATE`는 파일만 만들고 폴더는 안 만든다)
6. 재시작 후 `bNN` 7개가 다시 `ready` 인지 확인

용량 산정: 실측 기준 카메라 1대당 하루 약 9~10GB, 7대면 **하루 65~70GB 안팎**. 40일이면 **약 3TB**가 필요하므로 **4TB 이상**을 권한다. 정확한 값은 실측 명령으로 다시 재라.

### 4-3. 공유기 고정 IP 할당 (권장, 미완료)

카메라 IP가 DHCP라 정전·재부팅 후 바뀔 수 있고, 바뀌면 그 카메라 녹화가 조용히 끊긴다.
공유기(`192.168.0.1`, TP-Link_3827) 관리 페이지에서 위 표의 **MAC 주소 7개를 현재 IP로 고정 할당**하면 해결된다.

### 4-4. 감시견의 한계 (알아만 둬라)

`C:\cctv\watchdog.ps1` 은 **프로세스가 살아있는지만** 본다. MediaMTX가 살아있는데 특정 카메라만 끊긴 경우는 감지하지 못한다. 개선하려면 `http://127.0.0.1:9997/v3/paths/list` 로 `bNN` 7개의 `ready` 상태를 확인하는 로직이 필요하다. **대표와 상의 없이 바꾸지 마라.**

- 비전문가다. **친절하게, 한 번에 한 단계씩** 안내해라.

## 6. 상태 점검 명령 (문제 생기면 이것부터)

```powershell
# 1) 카메라 7대가 붙어 있나  (b01~b07 = True 면 정상, sub는 False가 정상)
Invoke-RestMethod http://127.0.0.1:9997/v3/paths/list | % items | Select-Object name, ready | Format-Table -AutoSize

# 2) 녹화가 실제로 쌓이나  (쓰는 중인 파일은 탐색기 크기가 0으로 보이므로 직접 열어서 잰다)
Get-ChildItem D:\cctv\recordings -Recurse -File | ForEach-Object {
  $fs=[System.IO.File]::Open($_.FullName,'Open','Read','ReadWrite')
  [pscustomobject]@{Folder=$_.Directory.Name; MB=[math]::Round($fs.Length/1MB,1)}
  $fs.Close() } | Format-Table -AutoSize

# 3) 로그
Get-Content D:\cctv\mediamtx.log -Tail 30

# 4) Tailscale
& 'C:\Program Files\Tailscale\tailscale.exe' ip -4
```

> **주의:** 위 2)번에서 일반적인 `Get-ChildItem | Measure-Object Length` 는 **0을 보고한다.** 윈도우가 열려 있는 파일의 디렉터리 항목 크기를 갱신하지 않기 때문이다. 정상인데 고장으로 오진하기 쉬우니 반드시 파일을 직접 열어서 재라.
